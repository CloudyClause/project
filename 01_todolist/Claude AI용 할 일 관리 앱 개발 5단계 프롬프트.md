# STEP 1. 앱 구조 및 개발 설계 확정

## 목적

PRD를 실제 개발 가능한 구조로 변환하고, 구현 전에 앱의 화면·컴포넌트·데이터 구조를 확정한다.

## Claude 입력 프롬프트

너는 모바일 앱 및 프론트엔드 개발 경험이 풍부한 시니어 개발자이자 UI/UX 설계 전문가다.

지금부터 모바일 중심의 할 일 관리 앱을 개발하려고 한다.

앱의 핵심 목표는 사용자가 복잡한 설정 없이 빠르게 할 일을 등록하고, 오늘 해야 할 일을 확인하고, 완료 상태를 관리하는 것이다.

### 핵심 서비스 방향

사용자의 기본 흐름은 다음과 같다.

앱 실행  
→ 오늘 해야 할 일 확인  
→ 할 일 추가  
→ 중요도 및 날짜 설정  
→ 완료 체크  
→ 완료 내역 확인

초기 MVP에서는 기능을 지나치게 확장하지 않는다.

### MVP 필수 기능

- 할 일 추가
- 할 일 수정
- 할 일 삭제
- 완료/미완료 변경
- 날짜 지정
- 중요도 지정
- 오늘 할 일 목록
- 날짜별 일정 확인
- 완료 목록
- 기본 설정
- 데이터 저장

### MVP에서 제외할 기능

- 반복 일정
- 고급 알림
- AI 추천
- 통계
- 외부 캘린더 연동
- 협업 기능

### 개발 방향

프론트엔드는 React 기반으로 설계한다.

상태 관리는 초기에는 React의 useState와 useEffect를 사용한다.

# STEP 3. Todo 핵심 기능 구현

## 목적

STEP 2의 UI에 실제 할 일 관리 기능을 연결한다.

이번 단계가 MVP의 핵심 기능 개발 단계다.

## Claude 입력 프롬프트

앞서 구현한 STEP 2의 React UI를 기반으로 기능을 추가한다.

기존 UI와 컴포넌트 구조를 최대한 유지하고, 기능 구현을 이유로 전체 코드를 불필요하게 다시 작성하지 마라.

이번 단계에서는 실제 Todo CRUD와 상태 관리를 구현한다.

### 반드시 구현할 기능

#### 1. 할 일 추가

사용자가 제목을 입력하고 할 일을 추가할 수 있어야 한다.

최소 입력값:

- title
- dueDate
- priority

title이 비어 있는 경우 등록되지 않도록 한다.

#### 2. 완료 상태 변경

체크박스를 클릭하면

```javascript
completed: false
```

에서

```javascript
completed: true
```

로 변경한다.

다시 클릭하면 미완료 상태로 돌아갈 수 있어야 한다.

#### 3. 수정

기존 할 일을 선택하면 다음 값을 수정할 수 있어야 한다.

- 제목
- 날짜
- 중요도

#### 4. 삭제

사용자가 할 일을 삭제할 수 있어야 한다.

가능하면 삭제 직후 일정 시간 동안 실행 취소할 수 있는 구조도 고려하되, 전체 구조가 지나치게 복잡해질 경우 MVP에서는 제외해도 된다.

#### 5. 중요도

중요한 할 일과 일반 할 일을 구분한다.

데이터:

```javascript
priority: "normal"
```

또는

```javascript
priority: "high"
```

중요 업무는 오늘 화면에서 시각적으로 구분한다.

#### 6. 오늘 할 일

오늘 날짜와 `dueDate`가 동일한 Todo만 오늘 화면에 표시한다.

#### 7. 완료율

오늘의 전체 할 일과 완료된 할 일을 기준으로 계산한다.

예:

```text
3 / 5 완료
60%
```

할 일이 0개일 때 오류가 발생하지 않도록 처리한다.

### State 기본 구조

필요하다면 다음 구조를 활용한다.

```javascript
const [todos, setTodos] = useState([]);
```

Todo 객체는 최소 다음 값을 유지한다.

```javascript
{
  id,
  title,
  completed,
  priority,
  dueDate,
  createdAt
}
```

id는 중복되지 않게 생성한다.

### 중요

React state를 직접 수정하지 마라.

예를 들어 다음 방식은 사용하지 않는다.

```javascript
todos.push(newTodo);
```

반드시 새로운 배열이나 객체를 생성해서 state를 업데이트한다.

### 결과물

1. 수정된 파일 목록
2. 각 파일 전체 코드
3. 새로 추가된 기능 설명
4. 주요 함수 역할 설명
5. 테스트 방법

을 제공하라.

마지막에는 다음 기능들이 실제로 동작하는지 체크하라.

- 추가
- 수정
- 삭제
- 완료
- 미완료 복원
- 중요도 변경
- 오늘 날짜 필터
- 완료율 계산

문제가 예상되는 부분이 있으면 함께 설명하라.

마지막으로 STEP 4에서 구현할 저장 및 날짜별 기능을 정리하라.

# STEP 4. LocalStorage + 일정/완료 데이터 연결

## 목적

앱을 새로고침하거나 다시 실행해도 Todo 데이터가 유지되도록 만들고, 일정 및 완료 화면을 실제 데이터와 연결한다.

## Claude 입력 프롬프트

STEP 3까지 구현된 React Todo 앱을 기반으로 기능을 확장한다.

기존 기능이 정상적으로 작동하는 상태를 유지해야 한다.

이번 단계에서는 다음 세 가지를 구현한다.

1. LocalStorage 데이터 저장
2. 일정 화면 실제 데이터 연결
3. 완료 화면 실제 데이터 연결

---

## 1. LocalStorage

앱을 새로고침해도 Todo가 사라지지 않도록 한다.

앱 최초 실행 시 LocalStorage를 읽는다.

예:

```javascript
const savedTodos = localStorage.getItem("todos");
```

데이터가 존재하면 JSON으로 변환한다.

Todos가 변경되면 LocalStorage에도 저장한다.

예:

```javascript
localStorage.setItem("todos", JSON.stringify(todos));
```

주의:

초기 렌더링 과정에서 기존 데이터가 실수로 빈 배열로 덮어쓰기 되지 않도록 로직을 검토한다.

JSON parsing 오류가 발생할 경우 앱 전체가 중단되지 않도록 방어 코드를 작성한다.

---

## 2. 일정 화면

달력에서 날짜를 선택하면 해당 날짜의 Todo만 표시한다.

기준:

```javascript
todo.dueDate === selectedDate
```

달력에는 Todo가 있는 날짜를 작은 dot 또는 표시로 표현한다.

지원 기능:

- 이전 달
- 다음 달
- 날짜 선택
- 선택 날짜 강조
- 해당 날짜 Todo 출력

필요하면 직접 간단한 달력 로직을 작성하거나, 라이브러리를 사용해야 한다면 왜 필요한지 설명한 뒤 최소한으로 사용한다.

---

## 3. 완료 화면

다음 조건의 Todo만 표시한다.

```javascript
todo.completed === true
```

가능하면 최근 완료한 업무가 먼저 보이도록 한다.

완료 시점을 관리해야 한다면 Todo 데이터에 다음 필드를 추가할 수 있다.

```javascript
completedAt
```

완료 처리할 때 현재 시간을 저장하고,

미완료로 변경하면:

```javascript
completedAt: null
```

로 처리한다.

### 데이터 마이그레이션

기존 LocalStorage 데이터에는 completedAt이 없을 수 있다.

이 경우에도 오류가 발생하지 않도록 기존 데이터와 호환되게 작성한다.

---

## 데이터 초기화

설정 화면의 데이터 초기화 기능도 실제로 연결한다.

데이터 초기화 버튼 선택 시 바로 삭제하지 말고 사용자에게 확인 절차를 제공한다.

확인 후:

- todos state 초기화
- LocalStorage 삭제

를 수행한다.

11. 데이터 초기화
12. 새로고침 후 데이터 삭제 확인

코드를 작성한 뒤 예상되는 오류 가능성도 검토하라.

마지막에는 STEP 5에서 수행할 최종 검수 항목을 정리한다.

# STEP 5. 최종 검수 · 오류 수정 · MVP 완성

## 목적

기능을 새로 크게 추가하는 것이 아니라 지금까지 개발한 앱을 실제 사용 가능한 MVP 수준으로 안정화한다.

## Claude 입력 프롬프트

지금까지 STEP 1~4에서 구현한 Todo 앱 전체를 최종 검수한다.

이번 단계에서는 새로운 대규모 기능을 추가하지 않는다.

목표는 현재 MVP를 안정적으로 완성하는 것이다.

### 1. 기능 검수

다음 기능을 하나씩 확인한다.

#### 오늘

- 현재 날짜 표시
- 오늘 Todo 필터링
- 중요 Todo 표시
- 완료율 계산
- 남은 할 일 수
- 완료/미완료 변경

#### Todo 관리

- 추가
- 수정
- 삭제
- 중요도 변경
- 날짜 변경
- 빈 제목 등록 차단
- 중복 이벤트 발생 여부

#### 일정

- 이전 달
- 다음 달
- 날짜 선택
- Todo 존재 날짜 표시
- 선택 날짜 Todo 필터링

#### 완료

- 완료된 Todo만 출력
- completedAt 처리
- 미완료 복원

#### 데이터

- LocalStorage 최초 로딩
- LocalStorage 저장
- 새로고침 데이터 유지
- 잘못된 LocalStorage 데이터 처리
- 데이터 초기화

#### 네비게이션

- 오늘
- 일정
- 완료
- 설정

모든 메뉴 이동이 정상적으로 작동하는지 확인한다.

---

### 2. React 코드 검수

다음 문제를 확인한다.

- state 직접 수정 여부
- 불필요한 useEffect
- useEffect 무한 반복 가능성
- key 중복
- 이벤트 중복 실행
- 불필요한 렌더링
- 잘못된 날짜 비교
- LocalStorage 초기화 문제
- null 또는 undefined 처리 문제

---

### 3. UX 검수

사용자가 다음 작업을 어렵지 않게 할 수 있는지 평가한다.

- 앱 실행 후 오늘 할 일 확인
- 빠른 할 일 등록
- 체크박스로 완료
- 잘못 추가한 Todo 수정
- 필요 없는 Todo 삭제
- 특정 날짜 일정 확인
- 완료 업무 확인

특히 **할 일 추가 → 확인 → 완료** 흐름이 복잡하지 않은지 검토한다.

---

### 4. 모바일 UI 검수

다음을 확인한다.

- 화면 가로 overflow 발생 여부
- 버튼 터치 영역
- 텍스트 잘림
- 긴 Todo 제목 처리
- 빈 화면 처리
- Todo가 많을 때 스크롤
- 하단 네비게이션과 콘텐츠 겹침
- 모바일 키보드 사용 시 입력창 문제

---

### 5. Empty State 추가

데이터가 없을 때 빈 화면처럼 보이지 않게 한다.

예:

오늘 할 일이 없는 경우:

```text
오늘 예정된 할 일이 없습니다.

새로운 할 일을 추가해보세요.
```

완료된 할 일이 없는 경우:

```text
아직 완료한 할 일이 없습니다.
```

일정이 없는 날짜:

```text
이 날짜에는 등록된 일정이 없습니다.
```

---

### 6. 오류 수정 원칙

오류를 발견하면 무조건 전체 코드를 다시 작성하지 마라.

다음 순서로 처리한다.

1. 오류 원인 확인
2. 문제가 있는 파일 확인
3. 문제가 있는 함수 또는 코드 블록 확인
4. 최소 수정
5. 다른 기능 영향 확인

기존에 정상 작동하는 기능을 수정 과정에서 훼손하지 마라.

---

### 7. 최종 결과 제출

최종 결과는 다음 형식으로 정리한다.

#### A. 프로젝트 구조

전체 파일 구조

#### B. 최종 코드

실행에 필요한 전체 코드

#### C. 구현 완료 기능

체크리스트 형태

#### D. MVP에서 제외된 기능

향후 Version 2.0 기능과 구분

#### E. 테스트 결과

각 기능의 정상 작동 여부

#### F. 알려진 제한사항

현재 구현에서 남아 있는 제약이나 위험 요소

#### G. 다음 개발 추천

Version 2.0 개발 우선순위

추천 순서:

1. 카테고리
2. 검색 및 필터
3. 반복 일정
4. 알림
5. 다크모드
6. 로그인
7. 클라우드 동기화

중요:

현재 MVP가 안정적으로 작동한다면 Version 2.0 기능을 실제 코드에 임의로 추가하지 마라.

최종 목표는 다음 핵심 흐름이 오류 없이 동작하는 것이다.

**할 일 등록 → 오늘 확인 → 중요도 확인 → 완료 → 일정 확인 → 완료 기록 → 데이터 유지**

이 흐름이 안정적으로 구현되었는지를 최종 기준으로 판단하라.
